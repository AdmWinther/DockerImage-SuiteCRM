# SuiteCRM Docker Image (PHP 8.1 / Apache)

A custom Docker image for **SuiteCRM 8.6.0**, built for the [Thusia platform](https://github.com/AdmWinther/Thusia-architecture), where SuiteCRM runs as one container in a Docker Compose stack.

The Bitnami SuiteCRM images was not available all of a sudden. I have already made my app using their image. So, there is one easy way around it, "To Make My Own Image!" simple as that. So this image builds SuiteCRM from source with a custom entrypoint that handles installation and configuration at container start.

## How it works

- **Base:** PHP 8.1 + Apache
- **Configuration via environment variables** — no credentials baked into the image. The entrypoint script runs SuiteCRM's CLI installer on first start using the supplied variables (`DB_USERNAME`, `DB_PASSWORD`, `DB_HOST`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `SITE_URL`, ...)
- **Persistence** — mount a volume over `/var/www/html`; the container detects an existing installation and skips reinstallation on subsequent runs

## Build

1. Download the SuiteCRM 8.6.0 source (.zip) from the [official SuiteCRM site](https://suitecrm.com/download/)
2. Extract it next to the Dockerfile and rename the folder to `SuiteCRM`
3. Build:

```bash
docker build -t <your-namespace>/suitecrm:8.6.0 .
```

## Run

Standalone:

```bash
docker run -d -p 8086:80 \
  -e DB_HOST=db -e DB_NAME=crm_db \
  -e DB_USERNAME=... -e DB_PASSWORD=... \
  -e ADMIN_USERNAME=... -e ADMIN_PASSWORD=... \
  -e SITE_URL=http://localhost:8086 \
  -v ./persist:/var/www/html \
  <your-namespace>/suitecrm:8.6.0
```

Or use the included **`compose.example.yml`** — a minimal local test stack (MariaDB + this image) with placeholder credentials, for development only.

## Why build a custom image?

In the Thusia stack, every service configuration is generated by Terraform from variables. That requires a CRM container that configures itself entirely from its environment at startup — including the quirks of SuiteCRM's installer, such as component IDs (e.g. for email templates) being generated at table-creation time, which means configuration must happen through the installer rather than by copying a pre-made `config.php`.
